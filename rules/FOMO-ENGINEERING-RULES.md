# FOMO engineering rules (one page — loaded into every coding session)

Full reasoning, checklists, estate map and the incident log behind each rule: `FOMO-ENGINEERING-GUIDELINES.md` in the same folder. Read it before touching anything scheduled, anything that calls Rentman/HubSpot/Xero, anything that writes Firestore, sends email, or deploys. Repo-specific rules (`.cursor/rules/*.mdc`, `CLAUDE.md`) still apply; these sit above them.

Jamie is not an engineer. If a rule blocks the request, stop and say which rule and why, in plain language. Don't work around it.

1. **Nothing fails silently.** Skipped or failed jobs return non-2xx (409 locked, 502 failed), never `200 {skipped:true}`. Every catch logs **and** `Sentry.captureException`. External-API helpers never return `[]`/`null`/`""` to mean "failed". A button reports the real outcome. Every scheduled job has an alert that reaches a person.

2. **Every scheduled job has an identity, a timeout, a lock and a free minute.** OIDC service account on Scheduler, no `allUsers` invoker. Explicit self-imposed timeout shorter than the interval, with an `INCOMPLETE` log line before the platform kill. Owner-tokened lock with a lease longer than the worst run. Check both Scheduler regions before picking a minute; never share one with a job touching the same lock or API; `*/5` jobs own :00/:05/:10… `attemptDeadline` > real duration. No `sleep()` as rate limiting.

3. **Work is incremental and idempotent.** Remember what was done (checkpoint / `lastCalculatedAt`), process only what changed, compare before writing, take the "fresh as of" stamp at the *start* of a run. Firestore writes touch only the fields they change (`set(...,{merge:true})` or `update`), never a whole document rebuilt from an earlier read. Window-based syncs get a reconciliation pass.

4. **Rentman is one shared quota.** One token, six apps, one circuit: when any caller trips it, deal creation pauses for an hour. All Rentman calls go through the guard (`lib/rentman-guard.ts` / `rentmanGet`), never raw `fetch`. State the per-run call budget in a comment. Nothing polls Rentman faster than 5 min or pulls a catalog more than once per run. Say in the PR summary if a change adds Rentman calls.

5. **Deploy, verify, don't trust the push.** Confirm the specific deploy happened (Actions/Cloud Build run, new revision, Vercel deployment) before saying "live". Runtime config that only lives on the service (memory, schedules, env var names) is also written in the repo. `npm test` + `npm run lint` with output shown; a fix to an untested module ships with a test or a written reason. Never delete on the strength of a note: verify against current code, jobs and data. Notes have been wrong three times this month.

6. **Scope and hand-off.** Surgical changes only; one PR per finding. **Standing go-ahead (Jamie, 22 Oct 2026):** once the change is checked (tests, lint, and a look in the browser for anything on screen), commit, push, open the PR, merge it and confirm the deploy is live, without asking. Stop and ask instead when a check fails or something couldn't be verified; when the change touches deal money/stage/close date, customer email, Rentman writes or payment status; when it adds a new scheduled job or service or changes Rentman call volume; or when it deletes data or does anything that can't be undone. Never read or print `.env*`, `*-secrets`, or secret values. Cheaper models implement specs; anything touching deal money/stage/close date, customer email, Rentman writes or payment status is a decision for Jamie, flagged not made. One exception (Jamie, 6 Oct 2026): approvers (Jamie, Sam, Will) may write to Rentman by pressing Push in the dashboard's kit onboarding, which only writes the plan they reviewed (hash-checked); code changes to that path are still flagged. A new job or service is not done until rules 1, 2 and 4 are satisfied.

7. **Decisions are written down the same day** (Jamie, 17 Nov 2026). Each app's decisions live in its `docs/DESIGN.md` (and `CLAUDE.md`). Claude checks every Slack #app-requests request against them, read fresh from GitHub, so they must be current. When Jamie decides something about an app in any chat, add it to that app's `docs/DESIGN.md` the same day in a small PR, dated, even if no code changes yet. A PR that changes how an app behaves updates the notes or says `No decision changed: <why>` under `## Design notes` (the "Design notes" check). A copy of this file is in `FOMORentals/fomo-app-requests/rules/` for the build robot: change both.
